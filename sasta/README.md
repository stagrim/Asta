# Sasta (Server-side of Asta)

Sasta is the backend engine for the Asta display management system. It exposes a RESTful API and a WebSocket server that manages the state of Displays, Playlists, and Schedules.

![Smiling Asta](img/smiling_asta.jpg "Smiling Asta")

## 🚀 API & Swagger Documentation

Sasta exposes a fully documented REST API for managing the system's entities.

Instead of reading raw JSON database schemas, you can interact with the live API documentation (Swagger UI) directly in your browser. This UI allows you to explore endpoints, inspect payload structures, and execute requests against your local database.

To access the Swagger UI:

1. Ensure Sasta is running (see the [Root README](../README.md)).
2. Open your browser and navigate to:
   ```
   http://127.0.0.1:<sasta-port>/swagger-ui
   ```

The Swagger documentation is automatically generated from the Rust source code using `utoipa` and stays perfectly in sync with the actual API.

## 📺 Using the built in Client (HTMX)

Accessible via a running Sasta instance at

```
http://127.0.0.1:<sasta-port>/casta/<display-uuid>
```

## 🛠 📺 Building a Client (Casta Protocol)

Sasta communicates with display clients using a lightweight WebSocket standard called the **Casta Protocol**.

While Sasta already hosts an out-of-the-box HTMX reference client, you can build your own custom display client in any language by connecting to the WebSocket endpoint and parsing the JSON payloads.

👉 **[Read the Casta Protocol Documentation](../casta_protocol/README.md)** for details on the handshake and WebSocket JSON structures.

## 📁 File Storage & Metadata

Sasta stores everything in two places:

- **Metadata:** All configurations (Displays, Schedules, Playlists, File Metadata) are stored in a Redis database.
- **Filesystem:** Any uploaded physical assets (like Images or PDFs) are saved directly to the filesystem and served by Sasta's internal file server. When deploying multiple Sasta replicas, you must ensure they share the same mounted filesystem for these assets.

## ⚙️ Environment Configuration

Sasta requires certain environment variables to configure its database connection and storage settings.

Create a `.env` file in the `sasta/` directory (or use the one generated by `dev/cargo run`). The available variables are:

| Variable    | Required | Default          | Description                                                                                                                                 |
| ----------- | -------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `REDIS_URL` | **Yes**  | None             | The connection string for the Redis database. Example: `redis://127.0.0.1:6379`                                                             |
| `ADDRESS`   | No       | `127.0.0.1:8080` | The IP and port to bind the Sasta API and WebSocket server.                                                                                 |
| `FILE_PATH` | No       | `./files`        | The directory on the filesystem where uploaded assets (Images, PDFs) are saved. Must be a shared volume if running multiple Sasta replicas. |
